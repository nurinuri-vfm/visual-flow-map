## アーキテクチャ図が読まれない理由

システムの全体図を描いたことがある人なら知っていると思います。あの図は**描いた瞬間から腐り始める**し、そもそも読む側は「この図、本当に今のコードと合ってるの？」を確かめる術がありません。

シーケンス図にも限界があります。1シナリオ=1枚なので、操作が100個あれば図も100枚。しかも「この関数を通る操作はどれか」という逆方向の問いには答えられません。

そこで、**AIエージェントに実コードを読ませてフロー図を作らせ、その内容を機械検証してから納品させる** Claude Code スキルを作りました。

## 何ができるか

生成されるのは自己完結したHTML 1枚です。CDN もサーバも不要、ダブルクリックで開きます。

- 上段に**操作のボタン**が並ぶ（「注文を確定する」「キャンセルする」…）
- 押すと、その操作が通る経路だけが**起点から順番に光る**（正常系=シアン、条件分岐=アンバー、失敗・再試行=レッド）
- 右側に手順が `ファイル:行番号` つきで並ぶ
- ノードをクリックすると**逆引き**（この処理を通る操作の一覧）
- マップはドラッグで移動、Ctrl+ホイールで拡大縮小
- `#flow=<id>` の**ディープリンク**で「この経路を見て」を Slack に貼れる

## 一番こだわった点：図が「信用できる」こと

AIに図を描かせる最大の不安は**ハルシネーション**です。もっともらしいが存在しない経路が混ざる。実際、このスキルの開発中も、検証エージェントを別に立てたら critical/high だけで19件の事実誤認が見つかりました（存在しないUIボタンの経路、呼ばれていないスクリプト、など）。

なのでスキルは「描く」だけでなく**検証のパイプラインごと**定義しています。

1. **並列抽出**: リポジトリを領域分割し、エージェントごとに JSON で書き出す（共有ノードのID規約を先に固定するのが肝）
2. **機械監査**: `audit.js` が ID分裂・参照切れ・重複フローを検出。`--repo` を渡すと**全ノードの `ファイル:行番号` の実在を検査**
3. **敵対的検証**: 抽出とは別のエージェントに「端から端までの鎖」を検証させる。「たぶん合っている」は報告禁止
4. **検証スタンプ**: 生成されたHTMLの隅に `コード参照 22/22 実在検証済み ・ commit abc1234 ・ 生成日` が焼き込まれる

受け取った人は、図の鮮度と検証状況をその場で確認できます。「AIが描いた図でしょ？」への答えを図自身が持っている、というのがこのスキルの一番の主張です。

## コードが無くても使える（事象フローモード）

レーンを技術レイヤ（画面/API/DB/…）から**主体**（保育士/保護者/外部機関/…）に入れ替えると、業務手順や事故対応の経緯も同じ形式で描けます。デモの2枚目は保育園の発熱対応（通常の引き渡し／緊急受診の2シナリオ）です。この場合の `ref` はコード行ではなく出典（`ガイドライン#条項` / `ヒアリング:相手`）になります。

設定は `meta.json` に書くだけで、テンプレートの編集は不要です。

```jsonc
{
  "title": "保育園 発熱対応の事象フロー",
  "flowWord": "事象",
  "lanes": [
    { "key": "staff",  "label": "保育士" },
    { "key": "parent", "label": "保護者" }
  ]
}
```

## 再生成すると「変わった場所」が光る（diff モード）

図が腐る問題への答えは「再生成を安くする」ことですが、再生成のたびに全部見直すのは辛い。そこで前回のHTMLを `--diff-base` に渡すと:

- 追加/変更されたノードに **NEW/変更** バッジ
- **「前回からの変更点」ボタン**が追加され、押すと追加された経路だけが光る（削除・変更は注記に列挙）
- ヘッダに「前回比 +3/変更2」

PRレビューで「この変更でどの経路が変わったか」を10秒で共有できます。

## 使い方

```
/plugin marketplace add ★your-github-id/interactive-flow-map
/plugin install interactive-flow-map
```

あとは Claude Code に頼むだけです。

```
このリポジトリの処理フローを可視化して。操作ごとにどこを通るのか追える図にして。
```

Agent Skills 標準（agentskills.io）準拠なので、対応する他のエージェントでも動くはずです（スクリプト実行に Node.js が必要）。

## まとめ

- フロー図は「描く」より「**検証して届ける**」が難しい。そこをスキル化した
- 単一HTMLなのでコードは手元から出ない。SaaS 不要
- コードのフローも、現実の出来事の流れも、同じ形式で描ける
